## 设计目标

让玩家从持枪、瞄准、开火、拉栓、装填和重新观察战场的连续动作中，感受到现有栓动步枪的重量与机械过程；让第一人称、AI 士兵、村庄和界面属于同一个世界。

采用用户已有设定：1938 年鲁南、台儿庄外围的一座虚构村庄，中国守军与日军围绕三处阵地作战。战斗布局与据点名称以 Combat Map V3 为准；旧背景文本中晒谷场等位置说明不能覆盖当前地图。具体部队、徽记与服装史实尚需单独核对，现有服装参考不等于完成考据。

## 当前基础与具体缺口

| 当前实现 | 应保留的基础 | 需要打磨的表现 |
|---|---|---|
| `Weapon.ts` | ADS、枪体/相机后坐、鼠标惯性、速度驱动摆动、奔跑放低 | 第一人称没有手部模型，缺少持握与操枪接触；枪身轮廓主要由方盒组成 |

## 第一项样板：三八式步枪的一次完整使用过程

| 状态 | 玩家应看到、听到的内容 | 验收重点 |
|---|---|---|
| 静止持枪 | 木托、机匣、枪管和瞄具轮廓清楚；双手支撑位置可信 | 枪和手比例统一，手指不悬空，枪身不遮挡主要观察区域 |
| 行走 / 奔跑 | 根据现有移速产生摆动与放低；停止后平顺稳定 | 保留现有输入响应；步枪不会持续漂移或随帧率改变摆幅 |
| 瞄准 | 照门、准星、瞄准方向建立清楚的视觉关系 | 对照实际射线与现有 ADS 投影检查；不以装饰准星掩盖对齐问题 |
| 开火 | 瞬时枪口反馈、枪体后坐、相机反馈和枪声起音相互对应 | 不改变命中计算、散布、伤害或开火判定顺序；不能用更大的抖动代替打磨 |
| 拉栓 | 手触及枪机，解锁、后拉、抛壳、前推、闭锁依次发生 | 手部与枪机接触连续，抛壳时刻复用现有事件，不新增一套独立计时器 |
| 装填 | 现有装填动作由手部、枪机和必要的视觉道具共同表达 | 手不穿过机匣；装填音与接触对应，视觉道具不拥有弹药逻辑 |
| 重新举枪 | 回到现有瞄准/持枪过渡，玩家能清楚辨认动作完成 | 完成时刻由原武器状态决定，表现动画不能提前或延后可开火时间 |

弹仓 5 发、栓动 1.5 秒、装填 3.2 秒及现有近战、射击规则作为不变量。手臂属于未来样板的表现资产；本文没有生成或添加手臂。

## 主题与资产规范

| 层面 | 统一原则 |
|---|---|
| 材质 | 先建立旧木、发暗钢件、棉布、皮革、土石五类基础。区分粗糙度与轮廓，控制磨损位置和纹理尺度 |
| 颜色 | 以当前灰黄土石、旧木褐、低饱和布料为环境基础。阵营 UI 继续使用既有辨识色，服装颜色由参考与可读性共同确定 |
| 士兵 | 帽形、上衣下摆、绑腿和携行装备形成远距离轮廓；站立、蹲下、移动时都可辨认。不能只靠把角色整体染成红蓝色 |
| 武器 | 第一人称与第三人称共享尺寸依据、轮廓、木金属分界和机械节点；近景可增加细节，远景可简化几何 |
| 村庄 | 通过墙体、屋顶、门洞、粮仓等既有建筑类型表达村镇身份；装饰服从视线、掩体、入口识别与通行空间 |
| UI | 战斗信息先保证可读；地域和年代感通过文字、配色、线框及页面构图体现，避免整屏装饰降低可读性 |
| 声音 | 保持既有机械动作、材料命中、脚步与地道空间反馈的因果关系。音色层次统一，环境氛围保留战斗提示的空间 |

建议固定三个检查场景：中性光近景、实际地表、实际地道。中性光便于发现模型和材质问题；实际场景用于检查亮暗变化和敌我辨认。暂不为武器增加独立灯光；是否需要补光必须由样板结果与性能测量决定。

## 同源资产的交付要求

每个正式资产需记录：稳定名称、源文件、游戏导出文件、尺寸与轴向、材质族、机械/握持节点、细节级别、参考来源、实际游戏预览和测量结果。

第一人称与第三人称不必使用完全相同的高精度网格，但应来自同一套设计定义。近景枪的枪机、枪托和准星不能与 AI 持枪外形变成不同款式。宣传图、检查器和游戏应使用实际导出资产；检查器可以改变相机和光照，但不能另外制作一份更精细的展示替身。

正式地图表现与碰撞代理分开记录；外观变化涉及可见掩体或入口时，必须核对视觉遮挡、物理碰撞、射线和导航是否一致。不能通过扩大或缩小模型悄悄改变当前 V3 路线。

## 后续实施顺序与验收

1. **一个步枪样板**：在现有机制下完成持握 → ADS → 一发射击 → 拉栓 → 装填 → 回到持枪。先用中性光和固定相机检查，再进入实际战场。
2. **近景与远景统一**：将该步枪的设计定义应用于 AI 持枪；选一名中国方、一名日军士兵检查衣袖、手部、装备和姿态的一致性。
3. **一组环境样板**：在独立检查场景中验证墙、木门、地面与角色的尺度和材质关系，再评估正式地图表现；不重排 V3 几何。
4. **UI 与声音复核**：使用同一段战斗过程检查提示层级、音画同步和环境转场，保持主题表达与战斗信息一致。

每一步只扩展已验收的样板。正式实施后的验收应同时包含真人操作、逐帧动作检查、原规则回归与同机同场景性能对照。真人重点判断：瞄准是否稳、动作是否清楚、枪是否有重量、手是否可信、声音是否帮助理解动作。

性能沿用 `PERFORMANCE_BASELINE.md` 的预算和采样方法：MEDIUM 为标准；固定池和 voice 上限不增加；AI 调度不回退。新资产允许改变网格数量，但必须明确记录增量，重新建立资产加载后的稳定对象基数，并验证跨回合不增长。不能将白盒的 290 个网格既当成永久美术上限，又直接沿用白盒性能结论。

本方案没有设定新的开发工期，也没有执行模型制作、代码实现、编译或重新测量。
